PART A — Backend
A1) shared/schema.ts: add `source: z.enum(["paper","live","manual"]).default("manual")` to
    incubationObservationSchema (keep the other fields).
A2) gates.ts: add a PURE, testable function (mirror computeMonteCarlo's style):
      computeIncubationVerdict({ observations, expectedReturn, expectedMaxDrawdown,
        periodComplete, requiredDays, elapsedDays })
    Logic with a named, documented constant:
      const DD_BLOWOUT_FACTOR = 1.5;  // forward DD may not exceed expectedMaxDrawdown * this
      - if !periodComplete -> { verdict: "cannot_evaluate", reason: "...N days remaining" }
      - if observations.length < 3 -> { verdict: "cannot_evaluate", reason: "min 3 observations" }
      - else compute avgReturn, avgDrawdown across observations:
          * FAIL if avgDrawdown > expectedMaxDrawdown * DD_BLOWOUT_FACTOR
            (forward drawdown materially worse than backtest)
          * FAIL if avgReturn < 0 (net-negative over the incubation period)
          * else PASS
      - returns { verdict, reason, metrics: { avgReturn, avgDrawdown, expectedReturn,
          expectedMaxDrawdown, ddTolerance: expectedMaxDrawdown*DD_BLOWOUT_FACTOR,
          observationCount, elapsedDays } }
      - reason must be honest when sources are "manual": note the verdict rests on
        self-reported forward data.
A3) routes/gates.ts incubation/evaluate: DELETE the `obs.some(() => false)` block. Call
    computeIncubationVerdict with strategy.performance as expectedReturn and
    strategy.maxDrawdown as expectedMaxDrawdown. Record the gate result; set its dataSource by
    provenance (all "live" -> "live"; any "paper" -> "paper"; else "self_reported"). On a
    pass/fail (not cannot_evaluate) call recordGate so the stage advances, like the other gates.
A4) gates.test.ts: add unit tests for computeIncubationVerdict — period incomplete and <3 obs
    -> cannot_evaluate; a drawdown blowout -> fail; net-negative return -> fail; healthy
